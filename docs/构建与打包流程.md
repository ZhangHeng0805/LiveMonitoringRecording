# 编译与打包流程

本文覆盖从源码到「双击即用」发行包的完整链路：环境准备 → 日常编译 → fat jar 打包 → 免安装发行包（exe + 内置 JRE）→ 版本升级 → 验证清单 → 常见坑。

> 日常改代码只需要「编译校验」；只有要出包给人用时才走「完整打包」。



***

| ------- | ------------------------------------ | ---------------------------------- |
| fat jar | `target/live-monitor-record-3.7.jar` | 约 194MB，含全部依赖与前端页面，`java -cp` 直接可跑 |
| 激活工具    | `target/activation-tool-3.7.jar`     | 生成 `xxxr-activation.lic`           |

## 3. 模块结构

根 `pom.xml` 的 `<modules>`（全部继承根版本 `3.7`）：



| 模块                                                   | 作用                                                |
| ---------------------------------------------------- | ------------------------------------------------- |

| `live-monitor-record`                                | 集成模块：`FileModeMain`（多房间）、HTTP 面板、shade 打成 fat jar |
| `douyin-start` / `bilibili-start` / `kuaishou-start` | 各平台取数与开播判定                                        |

| `douyin-fetcher`                                     | 抖音作品解析                                            |
| `cpolar-tool`                                        | 内网穿透（可选，发行包默认不带）                                  |

## 4. 日常编译（只校验，不出包）

改完代码先编译，确认没有语法 / 依赖问题：



```
# 只编公共模块（最快）
& $mvn -q -DskipTests -f 'F:\Git Project\LiveMonitoringRecording\pom.xml' -pl live-common -am compile

# 编集成模块及其依赖
& $mvn -q -DskipTests -f 'F:\Git Project\LiveMonitoringRecording\pom.xml' -pl live-monitor-record -am compile
```

要点：



* `-f` 必须带，`-pl` 单独用会找不到项目。

* `-am` 会把依赖模块一起编。

* 编译产物在各自 `target/classes`，**不会**更新 `target/*.jar`。

Get-Item 'F:\Git Project\LiveMonitoringRecording\target\live-monitor-record-3.7.jar', 'F:\Git Project\LiveMonitoringRecording\target\activation-tool-3.7.jar' |

## 6. 生成免安装发行包



```
pwsh 'F:\Git Project\LiveMonitoringRecording\build-tools\build-release.ps1'
```

参数：



| 参数                    | 默认                                                | 用途                                         |
| --------------------- | ------------------------------------------------- | ------------------------------------------ |
| `-Version`            | `3.7`                                             | 版本号，决定 jar 名、目录名、zip 名、exe 版本资源（`3.7.0.0`） |
| `-SkipBuild`          | 关                                                 | 复用已构建的 jar，不跑 Maven                        |
| `-SkipZip`            | 关                                                 | 只生成目录，不压缩                                  |
| `-OutDir`             | `dist\星曦向荣直播监听-<版本>-win64`                              | 自定义输出目录（调试时避免覆盖正式包）                        |
| `-FfmpegPath`         | 自动找 `bin\ffmpeg.exe`、`D:\直播录屏\...\bin\ffmpeg.exe` | 指定 ffmpeg                                  |
| `-ActivationToolPath` | 自动找 `target\activation-tool-<版本>.jar` 等           | 指定激活工具 jar                                 |

脚本内部 6 步：



1. **构建**（可 `-SkipBuild` 跳过）：`mvn -pl live-monitor-record -am package`，产出 fat jar。

2. **组装目录**：清空并重建 `lib`、`bin`、`room`、`cookie`、`logs`、`tools`；复制 jar、`build-tools/release-template/*`（配置模板、说明、bat）；`robocopy` 把 `%JAVA_HOME%\jre` 整体拷入；把 `javaw.exe` 复制一份命名为 `jre\bin\直播监听内核.exe`；复制 ffmpeg 与激活工具。

3. **生成图标**：`make-icon.ps1` 把 `live-common\src\main\resources\logo.png` 转成多尺寸 `app.ico`（16/24/32/48/64/128/256，PNG 内嵌）。

4. **编译启动器**：`csc /codepage:65001 /target:winexe /win32icon:app.ico` 编译 `Launcher.cs` → `直播监听.exe`（约 70KB）。`/codepage:65001` 必须保留，源码是 UTF-8 无 BOM，不加会让弹窗中文乱码。

5. **改写版本资源**：`rcedit.exe`（已放在 `build-tools/`，缺失时脚本尝试联网下载）写入 `FileDescription`、`ProductName`、`CompanyName`、`LegalCopyright`、文件 / 产品版本与图标。内核 exe 显示 “星曦向荣直播监听内核”，外壳显示 “星曦向荣直播监听”。

6. **压缩**：用 `ZipArchive` 逐文件写入，生成 `dist\星曦向荣直播监听-<版本>-win64.zip`（含顶层目录）。**`tools` 目录被排除**（激活工具单独分发），`room`、`cookie`、`logs` 三个空目录显式写入条目以保证解压后存在。

生成后的结构：



```
星曦向荣直播监听-3.7-win64/
├─ 直播监听.exe                启动器（双击入口，带图标与版本信息）
├─ xxxr.setting                配置模板（FILE 模式、ffmpeg 路径；不写 trialDays，默认 7 天）
├─ 使用说明.txt
├─ 安装监听浏览器.bat          首次联网安装 Playwright chromium（约 150MB）
├─ 获取设备标识.bat            打印本机设备标识（= 面板操作秘钥）
├─ 获取抖音登录信息.bat        扫码登录抖音 → cookie\DouYin.cookie + 自动启用 Cookie.DouYin
├─ 获取B站登录信息.bat         扫码登录 B 站 → cookie\Bili.cookie（不修改配置）
├─ jre/                        内置 JRE8（96MB）
│  └─ bin/直播监听内核.exe      javaw.exe 的副本，任务管理器显示的中文进程名
├─ lib/live-monitor-record-3.7.jar
├─ bin/ffmpeg.exe              录制用（101MB）
├─ room/                       直播间监听文件（*.room.json）
├─ cookie/                     平台登录 Cookie
├─ logs/                       运行日志：application.log、launcher.log、jvm.pid
└─ tools/                       （不进 zip，激活工具单独分发）
   ├─ activation-tool-3.7.jar
   └─ 生成激活文件.bat
```

启动器行为（`build-tools/Launcher.cs`）：



* 找 jar：优先 `lib\live-monitor-record-3.7.jar`，没有就取 `lib\live-monitor-record-*.jar` 里最新的（换版本不用改 exe）。

* 找 Java：优先 `jre\bin\直播监听内核.exe` → `jre\bin\javaw.exe` → `JAVA_HOME` → PATH。

* 单实例：启动后写 `logs\jvm.pid`；再次双击检测到进程存活就提示并直接打开面板，不再起第二个实例。

* 浏览器自检：`%LOCALAPPDATA%\ms-playwright` 下没有 `chromium-*` 时询问并调 `com.microsoft.playwright.CLI install chromium`。

* 日志：stdout/stderr 追加到 `logs\launcher.log`；找不到 jre/jar 或启动异常用 MessageBox 提示。

* 启动参数：`-Xmx512m -Dfile.encoding=UTF-8 -Dsun.stdout.encoding=UTF-8 ... -cp <jar> cn.zhangheng.lmr.FileModeMain ./room`。

### 6.1 登录信息脚本（抖音 / B站）

两个脚本不新增 Java 代码，直接复用 jar 里已有的 `main`：

* 抖音：`cn.zhangheng.douyin.browser.DouYinLogin` → 写 `cookie/DouYin-<昵称-ID>.cookie`
* B站：`cn.zhangheng.browser.login.BiliLogin` → 写 `cookie/Bili-<昵称-ID>.cookie`
* 后缀由 `BrowserLogin.FileSuffix = ".cookie"` 统一，与 `Constant.CookieFileSuffix` 保持一致。

脚本流程：检查 `jre` 与 `lib\live-monitor-record-*.jar` → 检查 `%LOCALAPPDATA%\ms-playwright\chromium-*`（缺了直接提示先装浏览器）→ 设 `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` → 用内置 `java.exe -cp <jar> <主类>` 拉起 Playwright 浏览器扫码登录（最长等 6 分钟）→ 取 `cookie` 下最新生成的文件复制成固定名 `DouYin.cookie` / `Bili.cookie` → 提示重启程序。**脚本不碰 `xxxr.setting`**。

要点：

* `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` 必须设：否则 `Playwright.create()` 发现浏览器版本不匹配会静默下载 150MB，国内网络下表现为“卡住不输出”。
* 配置值必须带 `file:` 前缀：`Setting.parseCookie` 只把 `file:` 开头的值当文件路径读取，否则会把整串当 Cookie 原文用。
* 脚本不修改配置：`Setting.getCookieDouYin()` / `getCookieBili()` 在 `Cookie.DouYin` / `Cookie.Bilibili` 为空时，会自动回退到 `cookie/DouYin.cookie`、`cookie/Bili.cookie`（`Constant.DefaultDouYinCookieFile` / `DefaultBiliCookieFile`，文件不存在则视为未配置），所以重跑登录脚本后只要重启程序即可。旧命名（`Bili.txt`、`*.room-cookie.txt`）不再兼容，老目录里的旧文件需重跑一次登录脚本生成新文件。

### 6.2 bat / 说明文件的编码（重要）

`release-template` 里的 `.bat` 和 `使用说明.txt` **必须是 GBK（cp936 / ANSI）**，并且第一行后跟 `chcp 936 >nul`：

* 原因：cmd 按“当前代码页”逐行解析批处理文件。UTF-8 保存时，含中文的行会被从多字节序列中间拆断，表现为某行中文变成 `'用手机' is not recognized as an internal or external command` 这类报错，后面几行也跟着错位。
* 不要用 UTF-8 + `chcp 65001` 去“修”：那是常见误区，实测仍会拆断中文行。
* 因此 bat 里调 Java 时用 `-Dsun.stdout.encoding=GBK -Dsun.stderr.encoding=GBK`，不要强塞 UTF-8 输出，否则 JVM 输出与 936 控制台不匹配，Java 打的中文照样乱码。
* 打包脚本会自动扫描模板 bat，发现 UTF-8 三字节中文序列就告警。

## 7. 版本升级要改哪里

从 3.7 → 3.8 时的清单：



1. 根 `pom.xml`：`<version>3.8</version>` 与 `<xxxr.version>3.8</xxxr.version>`（子模块版本与互相依赖的版本都靠这两处）。

2. 出包：`pwsh build-tools/build-release.ps1 -Version 3.8`（目录、zip、jar 名、exe 版本资源自动跟随）。

3. 启动器不用改：按 `live-monitor-record-*.jar` 通配查找。

4. 文档：`README.md`、`instructions.md` 里的版本号与示例 jar 名。

5. 用户迁移：新包是独立目录，把旧的 `xxxr.setting`、`room\*.room.json`、`cookie\`、激活文件复制过去即可；试用记录按 deviceId 绑定，换目录不重置。

## 9. 分发注意



* **必须整包分发**：只拷 `直播监听.exe` 会因为缺 `jre`、`lib` 直接报错。

* 首次使用需联网装监听浏览器（约 150MB），或提前把 `%LOCALAPPDATA%\ms-playwright` 一起拷到目标机。

* 发行包默认没有 `cpolar.exe` / `cpolar.setting`，此时程序只记一条 info「未配置内网穿透，跳过」，属正常。

* 压缩包里**没有** `tools` 目录（激活工具涉及私钥，单独发给需要的人）。对方要生成激活文件时，把 `tools` 解压到程序目录下，再双击 `tools\生成激活文件.bat`（脚本会自动切到上一级目录、自动匹配 `activation-tool-*.jar`）。

* exe 是用系统 `csc` 编译、再用 `rcedit` 改过资源的，部分杀软可能误报，放行整个目录即可。

* `dist/`、`target/` 都很大（单文件 100MB 级），不要提交到 Git。

## 10. 常见坑



| 现象                                                                | 原因 / 解决                                                                                                |
| ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `Unknown lifecycle phase ".file.encoding=UTF-8"` 之类               | pwsh 会把 `-Dxxx=yyy` 拆成多个参数，必须整体加引号：`"-Dfile.encoding=UTF-8"`                                           |
| `-pl live-monitor-record` 报 “Could not find the selected project” | 必须同时带 `-f <根 pom>`                                                                                     |
| 依赖 `com.zhangheng:ZH_Utils` 拉不到                                   | 未执行第 2.1 节的 `install:install-file`；国内直连 central 也可能超时                                                  |
| `mvn -o` 离线构建失败                                                   | 本地仓库缺插件 / 依赖，离线不可用，保持联网构建                                                                              |
| 控制台中文乱码                                                           | JDK8 默认 GBK：先 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`，运行参数加 `-Dfile.encoding=UTF-8`；**发行包里的 .bat 例外**，见 6.2 节：bat 存 GBK、Java 输出用 `-Dsun.stdout.encoding=GBK` |
| `build-release.ps1` 报「无法删除旧目录」                                    | 目录被记事本 / 资源管理器 / 终端占用，关闭后重试；调试可用 `-OutDir` 换目录；若只是目录句柄被占、里面已清空，脚本会告警并在原地继续生成                                                         |
| 启动器弹窗中文乱码                                                         | 编译时漏了 `/codepage:65001`                                                                                |
| 任务管理器显示 javaw / JDK                                               | 用的是旧包或没走 `直播监听内核.exe`；重新出包并确认 `jre\bin\直播监听内核.exe` 存在                                                  |
| 双击没反应                                                             | 看 `logs\launcher.log`（启动器）与 `logs\application.log`（程序）                                                 |
| 面板打不开                                                             | 端口可能被占自动后移，以日志 / 托盘提示为准；检查防火墙                                                                          |
| zip 解压后中文名乱码                                                      | 用 Windows 资源管理器或 7-Zip 解压；不要用老版本解压工具                                                                   |
